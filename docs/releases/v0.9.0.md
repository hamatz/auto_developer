# Auto Developer v0.9.0 リリースノート

**Version**: `v0.9.0`
**Date**: 2026-11-23

変更の一覧は [CHANGELOG.md](../../CHANGELOG.md) を参照してください（英語）。

---

## このリリースの位置づけ

v0.9.0 は、作者以外の人が使い始められることを目標にした最初のリリースです。次の3つを行いました。

- マルチチームの実行を、CLI とエージェントのスキルから使えるようにした。
- Checker の査読を、エージェントの申告ではなく Checker の出力そのものに結びつけ、あとから機械で確かめられるようにした。
- SPEC と README を書き直し、`pip install` → `auto-dev demo` で始められるようにした。

あわせて、意図して「歴史の断絶」を作りました。SPEC・LESSONS・README を書き直し（旧版は `docs/history/` に凍結）、以前の版の Evidence Bundle は受け付けません。

## 主な変更

- **マルチチームの実行**: `teams init` / `prepare` / `status` / `run` / `integrate` / `cleanup` / `recover`。チームごとに worktree とブランチ（`team/<id>`）を作り、統合では各チームの証跡を確かめ、順にマージして検証し直し、`integration/<job_id>` のブランチと `rc/<job_id>` のタグを作ります。main は変更しません。担当範囲（`owns`）の外を変えた作業は隔離します。
- **査読の証跡**: `review-input`（正規の差分）と `record-review`（Checker の出力・差分・SPEC の原文の切り出しを SHA-256 で記録）を追加しました。`commit-step` は、最新の検証に対応する APPROVE の記録がないとコミットしません。Bundle は査読の証跡を収録し、`verify-bundle` が照合します（`format_version` 3）。
- **`auto-dev demo`**: 外部のエージェントを使わずに、検証・査読・隔離・Bundle の検証までを1コマンドで見られます。
- **機密の保護**: `init` が `.gitignore` に `.env` を加え、`verify-step` / `commit-step` が `.env` や鍵ファイルのコミットを拒否します。`verify-step` は本物の Git のインデックスを変えなくなりました。Checker に渡す差分からは機密の行を除きます。
- **macOS と Linux のサンドボックスの修正**: python.org や GitHub Actions の Python（シンボリックリンク）で macOS のサンドボックスが起動できない不具合と、スレッドの多い Linux で bwrap が起動できない不具合を直しました。CI は macOS / Ubuntu × Python 3.10 / 3.12 で実行しています。
- **ドキュメント**: README（日本語・英語）を書き直し、README のコマンドはテストで実行しています。`docs/cli.md`（CLI の定義から生成）と `examples/two-teams/` を追加しました。

## 以前の版からの移行

- **Bundle**: `format_version` 3 未満の Bundle は検証できません。v0.8.0 以前の Bundle は v0.8.0 の `auto-dev` で検証してください。
- **エージェントの手順**: `record-review` は `--checker-output` / `--diff-file` / `--spec-file` が必要になりました（`--decision` だけの呼び出しは終了コード 2）。スキル（`/nightly-run`）は新しい手順に更新済みです。
- **`run` / `teams run`**: 外部コマンドを指定するときは、`--maker-model` / `--checker-model` が必要です。
- **`.env` などの機密のファイル**: コミットしようとすると拒否されます。`.gitignore` に加えてください。
- **計画ファイル**: `## ステップ` の見出しがあれば、その節のタスクだけを読みます。HTML コメントの中の行は読みません。
- **SPEC の ID**: 旧版の機能 ID（`機能WWW` など）は `docs/history/SPEC-v0.8.md` を参照してください。
- **タグ**: `v0.9.0` の形式になりました（v0.8.0 までは `v.0.8.0`）。

## 既知の問題

- `SECRET_FILE_IN_COMMIT` の検査は、日本語などを含むファイル名と、追跡している `.env` がシンボリックリンクから通常のファイルに置き換わった場合を見落とします（BACKLOG AUD-1004、AUD-1005）。
- リリース前の独立監査（`claude-opus-5-5`）は、Phase 70 の開始（`7ea39c0`）以降の変更を対象にしました。v0.8.0 からの差分全体は大きすぎて、1回の監査に入りませんでした。P0・P1 の指摘はなく、P2 の指摘2件を BACKLOG に入れました。
- 負荷の高い環境で、時間に依存する一部のテストが失敗することがあります。
- このリリースのための開発の途中の Bundle（Phase 70）は、途中で SPEC を変えたため `verify-bundle` で検証できません。リリースの判定には、最後のフェーズ（Phase 71）の Bundle を使っています。
